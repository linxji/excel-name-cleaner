# Excel 名称清理工具

> 一键清除 Excel / WPS 表格里堆积的无效定义名称 —— 不改动任何数据、公式与格式。

一个单文件、免安装、不联网的 Windows 小工具。专治「反复复制粘贴工作表 → 名称管理器里堆出几十万个无效名称 → 文件越用越大、打开越来越慢」的老毛病。

支持 `.xlsx` `.xlsm` `.xltx` `.xltm` `.xlsb` `.xls` `.et` `.ett`，同时兼容 Microsoft Excel 与 WPS Office。

---

## 为什么需要它

一个工作簿被反复复制、粘贴、另存，`xl/workbook.xml` 里的 `<definedNames>` 节点会不断累积。常见的情况是：

- 名称管理器里躺着 30 万个 `Sheet1!Print_Area_12345` 之类的东西，打开就卡死；
- 文件明明只有几百行数据，体积却有几十 MB；
- 双击打开要等十几秒，发给同事对方直接打不开。

手动删？名称管理器一次只能删一个。用 VBA 循环删？30 万个要跑两个小时。

---

## 功能

| 能力 | 说明 |
|---|---|
| **只删该删的** | 扫描全表公式，只删除**未被任何公式引用**和**已失效（`#REF!`）**的名称 |
| **零数据改动** | 数据、公式、格式、图表、数据验证、条件格式、打印区域全部保留 |
| **8 种格式** | `.xlsx` `.xlsm` `.xltx` `.xltm` `.xlsb` `.xls` `.et` `.ett` |
| **断开外链** | 可选，行为与 Excel 手动「断开链接」一致：公式转成当前数值，不出现 `#REF!` |
| **批量处理** | 拖入多个文件或整个文件夹，逐个处理互不影响 |
| **实时进度** | 进度条、当前文件、所处阶段、已用时、预计剩余、已删名称数、已减少体积 |
| **历史记录** | 每次处理都留档，可回看文件名、时间、名称数、用时、体积变化 |
| **后台运行** | 处理线程降到低于正常优先级，不干扰前台工作 |
| **纯本地** | 零网络请求，文件不出本机 |

## 实测效果

| 场景 | 名称数 | 耗时 | 体积变化 |
|---|---|---|---|
| 40 万个名称的 xlsx | 400,000 → 0 | 约 4 秒 | 1.1 MB → 69 KB |
| 31 表 + 外链 + 打印区 | 464 → 124 | 0.3 秒 | 减少约 10 KB |
| 数组公式 / 验证 / 条件格式 | 174 → 4 | 0.2 秒 | — |
| WPS `.et` / `.ett` | 226 → 6 | 0.3 秒 | — |

**保真验证**：处理前后用 WPS 打开，逐单元格比对公式与显示值，并比对合并区、列宽、填充色、名称表、数据验证、条件格式、打印区域 —— 全部 **0 差异**。

## 使用

1. 把表格文件（或整个文件夹）拖进窗口，或点「添加文件」
2. 按需勾选：保留打印区域 / 断开外部链接 / 后台模式 / 自动备份
3. 点「开始清理」

> 如果拖放没反应，通常是工具以「管理员身份」运行 —— Windows 会阻止低权限的资源管理器向高权限窗口拖文件。改用「添加文件」按钮即可。

## 工作原理

```
engine.detect()  ── 看文件头魔数
   ├─ PK..              → ooxml.py  （.xlsx/.xlsm/.xltx/.xltm/新版 .et/.ett）
   ├─ D0CF11E0..        → cfb 容器
   │                        ├─ EncryptedPackage → 加密，拒绝
   │                        └─ Workbook 流      → biff.py（.xls/老版 .et）
   ├─ PK.. + workbook.bin → xlsb.py（先转 .xlsx 再走 ooxml）
   └─ 其它              → 明确报错，不猜
```

三条硬约束：

1. **绝不重排 OOXML 的 XML** —— 全程用「字符串区间删除」改 `workbook.xml`，不用 ElementTree。一旦解析再序列化，命名空间前缀会被重写，Excel 会直接报「内容有问题」。
2. **BIFF 的名称是位置索引** —— 公式里的 `ptgName` 用 1-based 序号指向 NAME 记录，删记录后必须重映射全表序号。
3. **写入必须「临时文件 + 原子替换」** —— 目标被 Excel 占用时绝不能退化成「先删再替换」，那会删掉用户正在编辑的文件。

更多实现细节与踩过的坑，见 [`源码/开发者说明.md`](docs/开发者说明.md)。

## 开发历程

这个工具不是一开始就是独立 exe，它经历了四个阶段：

| 阶段 | 实现方式 | 30 万名称耗时 | 保留被引用名称 | 依赖 |
|---|---|---|---|---|
| R0 | VBA 分批 `Name.Delete` | 约 2 小时 | 否 | Excel + 宏 |
| R1 | VBA 逐个删 + 进度 | 约 71 分钟 | 否 | Excel + 宏 |
| R2 | VBA 改 zip 摘节点 | 约 1 秒 | 否 | Excel + 宏 |
| **v1.0.0+** | 解析 OOXML / BIFF | 约 4 秒 | **是** | 无 |

前三代 VBA 都能「删得动」，但都会把被公式、数据验证、图表引用的名称一起删掉，公式立刻变 `#NAME?`，而且必须装 Excel 才能跑。三个原稿存档在 [`源码/历史版本VBA/`](legacy-vba/)。

完整变更记录见 [CHANGELOG.md](CHANGELOG.md)。
