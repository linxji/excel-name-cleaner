# Excel 名称清理工具 · 开发者说明

**开发者：Opera-Jin**（AI 辅助开发）　|　版本 v1.4.0

本目录是完整源码，可自由查阅、修改、重新打包。
发布版为单文件 `Excel名称清理工具.exe`，不依赖 Python 环境；下面说明如何从源码跑起来和重新打包。

> 说明：本文档同时用于 GitHub 仓库和分享包。文中「项目根目录」在仓库里是仓库根，
> 在分享包里对应 `源码/` 文件夹；`legacy-vba/` 对应分享包内的 `源码/历史版本VBA/`。

## 二、从源码运行

```bash
pip install -r requirements.txt
python src/main.py                 # 直接启动界面
python src/main.py 某文件.xlsx      # 启动并预载文件
```

需要 Python 3.10+（开发时使用 3.14）。界面用 tkinter，Windows 自带。

## 三、重新打包

```bash
pip install pyinstaller pywin32
python build.py
```

产物在 `dist/Excel名称清理工具.exe`（约 14 MB，单文件，无控制台）。
`build.py` 里已经带好这些关键参数：

| 参数 | 作用 |
|---|---|
| `--onefile --windowed` | 单文件、不弹黑框 |
| `--add-data assets/app.ico;.` | 把图标塞进包内，运行时从 `sys._MEIPASS` 读 |
| `--hidden-import win32com.client / pythoncom / pywintypes` | `.xlsb` 转换要用 COM，PyInstaller 静态分析抓不全，必须显式声明 |
| `--version-file build/version_info.txt` | 写入文件版本信息，减少杀软误报 |

> 若只改界面、不需要 `.xlsb`，可以去掉 pywin32 相关参数，exe 会瘦到 12.8 MB。

## 四、项目演进史

本工具经历了从 VBA 宏到独立 exe 的四个阶段。三个 VBA 版本的原稿存放在
`legacy-vba/`，可以直接打开对照。

### 阶段 1 · R0 分批删除（GPT 对话生成）

文件：`R0_分批删除_初版.txt`

`Name.Delete` 逐个删太慢，改成每批 500 个，同时关闭屏幕刷新、事件、自动重算；
连续 5 批没有进展就停手，最多 1000 批防死循环。30 万名称约 **2 小时**。

问题：慢；而且「全部删光」，引用这些名称的公式全部变成 `#NAME?`。

### 阶段 2 · R1 逐个删除 + 进度（GPT 对话生成）

文件：`R1_逐个删除_进度版.txt`

改为倒序逐个删（`For i = TotalNames To 1 Step -1`），每 5 秒刷新状态栏，
带百分比、速度、已耗时、剩余时间。开头按实测速率（约 71 个/秒）预估耗时：
30.3 万个名称 ≈ **71 分钟**。

速度没有本质变化，仍然是整块删光。

### 阶段 3 · R2 直接改 zip（WorkBuddy 第一次优化 VBA）

文件：`R2_快速版v1.2.bas`（原 `.xlsm` 宏）

关键洞察：`.xlsx / .xlsm` 本质是 zip 包，所有名称都在 `xl/workbook.xml`
的 `<definedNames>` 节点里，直接摘掉这个节点即可，不需要几十万次 COM 调用。
30 万名称从 2 小时降到 **约 1 秒**。配套自动备份、状态栏进度、
`.xlsb / .xls` 走转换法、剩余少于 10 个时自动删备份。

**遗留问题**：整块摘除会连被引用的名称一起删。数据验证下拉、图表系列、
条件格式一旦引用了名称，立刻变成 `#NAME?`。VBA 里没有可靠的公式解析能力，
无法判断「哪个名称被引用了」。

### 阶段 4 · v1.0.0 起：独立 exe

放弃 VBA 的四个原因：

1. 必须依赖 Excel 本体，还要允许运行宏
2. 速度受 COM 调用限制，几十万次是小时级
3. 改 zip 虽快，但只能「全删」，分不清引用关系
4. 分发困难 —— 要教同事开宏、导入 `.bas`、改信任设置

改用 Python 直接解析 OOXML 与 BIFF8 后，四个问题同时解决：
秒级处理、精确判断引用、零环境依赖、双击即用。

### 各阶段对比

| 阶段 | 实现方式 | 30 万名称耗时 | 保留被引用名称 | 运行依赖 |
|---|---|---|---|---|
| R0 | 分批 `Name.Delete` | 约 2 小时 | 否 | Excel + 宏 |
| R1 | 逐个删 + 进度条 | 约 71 分钟 | 否 | Excel + 宏 |
| R2 | 改 zip 摘节点 | 约 1 秒 | 否 | Excel + 宏 |
| **v1.0.0+** | 解析 OOXML / BIFF | 约 4 秒 | **是** | 无 |

## 五、架构要点

处理流程是「先识别格式，再分派给对应引擎」：

```
engine.detect()  ── 看文件头魔数
   ├─ PK..           → ooxml.py    （.xlsx/.xlsm/.xltx/.xltm/新版 .et）
   ├─ D0CF11E0..     → cfb 容器
   │                     ├─ 有 EncryptedPackage → 加密，拒绝
   │                     └─ 有 Workbook 流      → biff.py（.xls/老版 .et）
   ├─ PK.. + workbook.bin → xlsb.py（先用 Excel/WPS 转 .xlsx，再走 ooxml）
   └─ 其它            → 明确报错，不猜
```

### 三条必须遵守的约束

1. **绝不重排 OOXML 的 XML**
   `ooxml.py` 全程用「字符串区间删除」改 `workbook.xml`，不用 ElementTree。
   一旦用 ET 解析再序列化，命名空间前缀会被重写，`mc:Ignorable="x14ac xr"` 里的
   前缀对不上，Excel 会直接报「内容有问题」。

2. **BIFF 的名称是位置索引**
   公式里的 `ptgName` 用 1-based 序号指向 NAME 记录。删记录后序号整体前移，
   必须把所有 `ptgName` 的序号一起改（`biff._renumber`）。
   `FORMULA / ARRAY / SHRFMLA / TABLE / NAME` 可精确解析；
   条件格式 `CF` 与数据验证 `DV` 的布局各家不同（WPS 与 MS-XLS 不一致），
   改用 `0x23/0x43/0x63 + 合法序号` 的字节特征做保守替换。

3. **写入必须是「临时文件 + 原子替换」**
   目标文件被 Excel 占用时 `os.replace` 会抛 PermissionError，
   这里**不能**退化成「先删再替换」—— 那会把用户正在编辑的文件删掉。

### 其它已经踩过的坑（改代码时注意）

- **数字字符实体**：有些工具把中文写成 `&#20851;`，公式里的名称识别不出来，
  会被误判为「未被引用」而误删。必须 `util.unescape_full()` 之后再匹配。
- **ARRAY 记录偏移**：`ref(6) + grbit(2) + chn(4) = 12`，`cce@12 / rgce@14`。
  偏移错 2 字节就会漏掉数组公式里的名称引用（典型受害者：`_xlfn.SINGLE`，即 `@` 运算符）。
- **INDEX.rgibRw 是流内绝对偏移**，删字节后要整体前移；只改「确实指向 DBCELL(0xD7 0x00)」的项。
- **SUPBOOK 内/外部判定**：Excel 用 `ctab=0x0401` 标自身，WPS 直接写工作表数量。
  可靠判据是记录长度：内部/加载项只有 2~4 字节，外部一定带路径字符串。
- **断开外链要转数值**：删 `<f>` 保留 `<v>`；字符串结果（`t="str"`）必须转成
  `t="inlineStr" + <is><t>…</t></is>`，否则常量单元格用 `t="str"` 是非法的；
  公式一变必须删掉 `xl/calcChain.xml` 及其实体/关系，否则 Excel 提示需要修复。
- **`str.replace` 默认替换全部**：给某个锚点打补丁前先 `assert s.count(anchor) == 1`。

## 六、测试

```bash
python tests/suite.py
```

会用本机 WPS（`Ket.Application`）打开「处理前 / 处理后」两份文件，逐单元格比对
公式与显示值，并比对合并区、列宽、填充色、名称表。全部通过才算过关。

> 本机 Excel 的 `Workbooks.Open` 曾被策略禁用，所以校验器默认走 WPS；
> 若你机器上 Excel 自动化可用，把 `validate_wps.py` 里的 ProgID 换成 `Excel.Application` 即可。

样本在 `tests/samples/`，也可以自己用 `tests/make_*.py` 重新生成。
